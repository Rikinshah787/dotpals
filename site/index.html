    See what your coding agent actually did.

    dotpals is a small floating pal that watches Claude Code, Codex or any coding agent and checks its work: what it changed, what it ran, and whether the tests really passed. When Claude breaks the tests, dotpals sends it back to fix them. And any AI tool can ask dotpals what really happened.

    New in 0.10 Make agents fix failing tests

    “Done, all tests pass.” Not so fast.

    Agents say “done” in one fluent line. dotpals reads what the tests actually printed, and when Claude Code broke them, it sends Claude back to fix them before it finishes, commits or pushes.

    • Told at once, with why. “expected 3, got -1 (test/math.test.js:5)”, read from the output of Jest, Vitest, pytest, Go, Cargo and more, not just the exit code. “0 tests ran” is never a pass.
    • Sent back, not stuck. Finishing, committing or pushing while its tests fail, or after a change it didn’t test: back to work, at most twice per request. Then the pal tells you.
    • Catches the faked pass. Green only because a test lost an assertion, got a skip or now expects the wrong thing? dotpals sees it, even through sed or a script, sends Claude back once and tells you.
    • Fair. Tests that were failing before Claude changed anything are reported, not forced on it. “Run the tests and tell me” just reports. Projects without tests are never held up.
    • Your switch. On by default for Claude Code. Turn it off from the gear in the notch, or in Settings. Unclear results can still get a second opinion from Laya (on your computer) or Jev (cloud), off by default.

    The test-output rules build on claude-referee by Ismail Daşcı (MIT). Laya is by Convai Innovations; Jev is by TypeSafe.

    New in 0.10 Ask dotpals from any agent

    Every AI tool can ask what really happened.

    dotpals mcp is an MCP server. Claude Code, Codex, Cursor and other assistants ask dotpals what your agents did, and get the evidence instead of the agent’s word.

    • check_my_work. An agent asks before it says “done”: “Looks done”, or what to fix first. Codex and Cursor too, which hooks can’t hold back.
    • ready_to_merge. “Is feat/login ready?” Every check a reviewer would make, ✓ or ✗.
    • today, recap, risky_steps. Your standup, what each agent did and why its tests failed, and every force push or .env change, with the command.
    • handoff_note. Pick up a session’s work in another agent.
    $ claude mcp add dotpals -- npx dotpals mcp

    01 The story view

    Four hundred tool calls. Five lines.

    A single request can read dozens of files, edit a handful, run the tests, retry and push. dotpals folds all of it into a few chapters you can read in five seconds, next to what the agent says it did.

    And it flags what deserves a second look:

    • it touched .env or another file that usually holds secrets
    • it force-pushed, ran a recursive delete or threw away changes
    • the same command failed 3 times in a row

    Every step is still one click away, with the exact command, its output and the diff.

        06 Local and private

        Nothing leaves your computer.

        A small local server, the bridge, turns what your agents report into one activity feed. It listens only on 127.0.0.1, only answers your own computer, and sends nothing anywhere unless you turn on the cloud test check.

        • History is a plain JSON file in ~/.dotpals, kept 7 days by default.
        • DOTPALS_HISTORY=0 turns history off. Clear it any time in Settings.
        • No account, no sign-up. MIT licensed, so you can read every line.
        • The MCP server only reads, from the bridge on your computer. Your AI tool asks it locally.
        • The test double-check is off by default. Local (Laya) stays on your computer; Cloud (Jev) sends only an unclear run’s output, with passwords, keys and emails removed.
